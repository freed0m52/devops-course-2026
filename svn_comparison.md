# Git vs SVN: краткие ответы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит.
Создать её — мгновенно, не копируя файлы.

В SVN ветка — это копия директории на сервере. Чтобы создать ветку,
сервер физически копирует файлы, что медленно и затратно по месту.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, SVN — централизованная система: все коммиты уходят на один сервер.
Без сети коммит невозможен.

В офлайне можно только:
- редактировать файлы локально;
- смотреть локальные изменения.

А вот `commit`, `log`, `diff` с историей — только при подключении к серверу.

В Git коммит делается локально, интернет нужен только для `push`/`pull`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты (госсектор, банки): уже есть инфраструктура, миграция дорога.
- Очень большие бинарные файлы (дизайн, видео): SVN умеет хранить их
  без раздувания истории, Git — плохо.
- Жёсткий централизованный контроль (нельзя, чтобы у всех была полная копия).
- Команда без опыта Git: SVN проще в освоении для новичков.
- Мелкие проекты с одним разработчиком, где не нужны ветки и офлайн-работа.
