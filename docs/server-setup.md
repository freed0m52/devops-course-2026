# Конфигурация виртуальной машины devops-vm

Документ описывает целевую конфигурацию учебного сервера `devops-vm`,
созданного в рамках практической работы №5 (дисциплина «Инструменты DevOps»).
Используется как исходный документ для восстановления конфигурации после
отката к снимку `01-clean-install`, а также как основа для написания
Ansible-роли в практической работе №11.

## 1. Параметры машины

- Объём оперативной памяти: **2048 МБ**
- Количество ядер процессора: **2**
- Объём дискового накопителя: **25 ГБ** (динамически расширяемый)
- Гипервизор: VirtualBox 7.x
- Гостевая ОС: **Ubuntu Server 24.04.5 LTS** (64-bit)

## 2. Сетевые интерфейсы

| Интерфейс | Тип адаптера | IP-адрес       | Назначение                                        |
|-----------|--------------|----------------|---------------------------------------------------|
| enp0s3    | NAT          | 10.0.2.15/24   | Доступ в интернет (обновления пакетов)            |
| enp0s8    | Host-only    | 192.168.56.101/24 | Прямой доступ с хостовой системы (SSH, HTTP)   |

Адрес Host-only используется для подключения по SSH, а также для доступа
к веб-серверу Nginx из браузера хостовой системы в практической работе №6.

## 3. Правило проброса портов (NAT, адаптер 1)

| Имя | Протокол | Порт хостовой системы | Порт гостевой системы |
|-----|----------|-----------------------|-----------------------|
| SSH | TCP      | 2222                  | 2222                  |

Проброс портов необходим для установления SSH-соединения с виртуальной
машиной через NAT-интерфейс (обращение к `127.0.0.1:2222` с хоста).

## 4. Учётные записи

| Имя     | Группы          | Способ аутентификации                               |
|---------|-----------------|-----------------------------------------------------|
| student | student, sudo   | пароль (используется для входа через консоль ВМ)    |
| devops  | devops, sudo    | SSH-ключ ed25519 (`~/.ssh/devops_vm` на хосте)      |

Для доступа к серверу используется отдельная ключевая пара
`~/.ssh/devops_vm` (генерируется на хосте командой `ssh-keygen -t ed25519`),
открытая часть размещена в `~/.ssh/authorized_keys` пользователя `devops`.

## 5. Служба SSH

- Порт: **2222**
- Основной файл конфигурации: `/etc/ssh/sshd_config` (не модифицируется)
- Дополняющий файл конфигурации: **`/etc/ssh/sshd_config.d/99-hardening.conf`**
- Директива `PasswordAuthentication` в `/etc/ssh/sshd_config.d/50-cloud-init.conf`
  закомментирована (иначе она имеет приоритет над `99-hardening.conf`
  из-за лексикографического порядка чтения).

Изменённые директивы в `99-hardening.conf`:

| Директива              | Значение | Назначение                                       |
|------------------------|----------|--------------------------------------------------|
| Port                   | 2222     | Нестандартный порт для снижения шума сканеров    |
| PermitRootLogin        | no       | Запрет входа от имени root                       |
| PasswordAuthentication | no       | Отключение парольной аутентификации              |
| PubkeyAuthentication   | yes      | Разрешение только ключевой аутентификации        |
| PermitEmptyPasswords   | no       | Запрет пустых паролей                            |
| MaxAuthTries           | 3        | Ограничение числа попыток аутентификации         |
| LoginGraceTime         | 30       | Таймаут ожидания аутентификации (секунды)        |
| AllowUsers             | devops   | Разрешение входа только пользователю devops      |
| X11Forwarding          | no       | Отключение X11-форвардинга                       |
| ClientAliveInterval    | 300      | Интервал проверки активности клиента (секунды)   |
| ClientAliveCountMax    | 2        | Число пропущенных проверок до разрыва сессии     |

Дополнительно отключена сокет-активация SSH (актуально для Ubuntu 24.04):

```bash
sudo systemctl disable --now ssh.socket
sudo systemctl enable  --now ssh.service
```

## 6. Правила межсетевого экрана (UFW)

Политики по умолчанию:

- `default deny incoming`
- `default allow outgoing`
- `disabled routed`

Активные правила:

| Порт      | Действие | Комментарий             |
|-----------|----------|-------------------------|
| 2222/tcp  | LIMIT    | SSH rate-limited        |
| 80/tcp    | ALLOW    | HTTP                    |
| 443/tcp   | ALLOW    | HTTPS                   |

Логирование: `medium` (записи в `/var/log/ufw.log`).

Правило для SSH задано через `limit` — источник, инициировавший 6 и более
соединений за 30 секунд, временно блокируется (защита от перебора).

## 7. Снимки состояния виртуальной машины

| Имя                | Когда создан                                |
|--------------------|---------------------------------------------|
| 01-clean-install   | После чистой установки Ubuntu Server 24.04  |
| 02-keys-configured | После настройки ключевой аутентификации     |
| 03-ssh-hardened    | После усиления защиты SSH и настройки UFW   |

Снимок `01-clean-install` используется как точка отката для проверки
воспроизводимости конфигурации по настоящему документу.

## 8. Порядок восстановления конфигурации из снимка 01-clean-install

1. Откатить ВМ к снимку `01-clean-install`.
2. Войти в консоль под пользователем `student`.
3. Создать пользователя `devops` и добавить его в группу `sudo`:
   ```bash
   sudo adduser devops
   sudo usermod -aG sudo devops
   ```
4. Разместить открытый ключ в `~/.ssh/authorized_keys` пользователя `devops`
   (права: каталог `~/.ssh` — 700, файл `authorized_keys` — 600).
5. Создать файл `/etc/ssh/sshd_config.d/99-hardening.conf` с директивами из п.5.
6. Закомментировать `PasswordAuthentication yes`
   в `/etc/ssh/sshd_config.d/50-cloud-init.conf`.
7. Проверить конфигурацию: `sudo sshd -t`.
8. Отключить сокет-активацию и перезапустить сервис:
   ```bash
   sudo systemctl disable --now ssh.socket
   sudo systemctl enable  --now ssh.service
   sudo systemctl restart ssh
   ```
9. Настроить UFW: политики по умолчанию + правила для 2222/tcp (LIMIT),
   80/tcp, 443/tcp. Включить: `sudo ufw enable`.
10. Прописать на хостовой машине в `C:\Windows\System32\drivers\etc\hosts`
    строку `192.168.56.101 devops.local`.
